# CoachLoop-FS V1.1 本地自适应备课

## 交付与使用边界

基于远程 main `7c72b13`；核查时 PR #10 尚未合并，安全继承其提交 `730a69d`，保留全部既有测试与启动器。本分支不改 main，不接 Coze，不部署。现有 V1 API/插件仍只支持原模板；V1.1 是同一本地控制台的独立扩展，不静默改变已发布契约。

24 个主题均为 **工程整理的候选教学条目**，`verification_status=unverified`，`source.reference=null`，版本 `1.1.0`。没有声称经过课程标准核验或专业教练批准。所有动作、安全条件、先修顺序、观察指标均待专项教练确认；无跳跃训练。没有调用大模型、知识检索、MediaPipe 或数据库。

## Mac 最简启动

取得本分支完整代码后，先停止旧服务（原终端 Ctrl+C），在 Finder 双击 **`scripts/start_prelesson_console.command`**。浏览器打开 **http://127.0.0.1:8767**。沿用原 Python 3.12+ 和已安装项目依赖，不新增运行依赖、不自动安装。不需要数据库变量、Token 或 Coze 账号。保留终端；Ctrl+C 停止。端口被占用或依赖缺失时非零退出，不静默改端口。

界面按水平筛选、中文/英文搜索主题。按实际条件填报师资、完整个人装备、可用面积和现场拟定容量，逐项勾选确已掌握的先修技能。容量是**未独立核实的教师声明**，不是系统认证的安全人数；确认组织方案与专项安全前不得实施。

教师可修改候选目标和三个核心练习、填写修改备注，再点击生成。空白练习编辑沿用主题库候选内容；修改保留 `catalogue_task` 原内容及“教师修改候选练习（未审核）”标记。下载 JSON 含七要素、完整教案、分组、人员分工、评价、负荷与审核清单。修改不等于批准，无审核身份认证或写回。

## 主题与输入

| 最低水平 | 六个主题 |
| --- | --- |
| 零基础 | 安全与装备、跌倒起立、冰上踏步、冰上双足滑行与身体姿态控制、身体姿态控制、基础停止 |
| 初级 | 交替蹬冰、单足滑行、葫芦步、后退双足滑行、双足转体、弧线滑行 |
| 初中级 | 前进内刃、前进外刃、后退单足、前进交叉步、圆周滑行、节奏控制 |
| 中级 | 后退内外刃、后退交叉步、三转基础、莫霍克步、双足旋转、基础步法组合 |

较高水平可以复习低水平主题，同时改变目标、练习方式与观察指标；低水平申请更高主题返回 `needs_confirmation`，不提供冰上实施方案。

输入包括匿名标签、主题 ID、学生人数、四个水平、儿童/青少年/成人/混龄、已掌握技能 ID、教练与体育教师人数、45 分钟、可用面积、现场拟定同时练习容量、完整冰鞋护具套数、冰外等待区、冰面可用性、场地与器材限制、目标偏好及教师修改。所有未知字段拒绝；人数不接受布尔值或小数，非有限面积、控制字符、未知/重复技能与文字师资冲突均拒绝。1–500人数、0–50师资、面积上界等仅是软件录入边界，绝非医学或专业安全阈值。

## 自适应组织与实际计算

- 不虚构师资。每轮指导组不多于实际教练数，末轮不生成空组；每名学生在一个轮次的一个组中。教练安排指导/观察/反馈，体育教师负责等待区与交接，不自动替代专项教练。
- 分组取教师填报的同时练习容量；不凭面积推定安全容量，不设“官方师生比”。面积及限制保留在场地与审核清单，交由现场核定。
- 45 分钟固定三阶段 **9 + 29 + 7**。基本阶段为示范5分钟+轮换24分钟。每轮转换1分钟是明确标注的设计假设；核心活动窗口为 `24 - 轮数`，每轮均分，三个递进任务再均分该轮核心活动时间。
- 预计人均活动时间为准备4分钟+结束3分钟+核心活动窗口/轮数；“群体活动窗口”仅指至少一组活动，不代表全班同时运动。密度复用既有 `LoadMetric` 原始精度核算，展示才舍入，不设置“达标”阈值。
- 不猜测心率：`avg_hr=null`，未估计、未实测。实际心率及实际密度仍需课堂测量；不能由本稿判断生理负荷或医学安全。
- 0教练、装备不足、无等待区、冰面不可用、缺先修、主题水平不匹配、存在轮换但无等待区负责人员，以及轮换过多导致无核心活动窗口时，返回 `needs_confirmation`，核心练习/指导组/分工为空、活动密度为0。保留45分钟条件核对框架，明确暂缓冰上实施；调整资源、复核先修或选择更基础主题后重新生成。

同一双足滑行主题，假设面积200平方米、现场拟定容量10人、30套装备、1名体育教师且先修已自报掌握：

| 场景 | 分组轮换 | 指导教练 | 预计人均核心活动 | 预计人均活动密度 |
| --- | --- | --- | --- | --- |
| 10人/2教练/零基础 | 1轮，每轮2组各5人 | 2名 | 23分钟 | 66.67% |
| 20人/1教练/零基础 | 2轮，每轮1组10人 | 1名 | 11分钟 | 40.00% |
| 20人/2教练/初级 | 2轮，每轮2组各5人 | 2名 | 11分钟 | 40.00% |
| 30人/1教练/零基础 | 3轮，每轮1组10人 | 1名 | 7分钟 | 31.11% |

第三个场景的目标改为左右侧稳定性，练习方式改为分侧重复比较，评价增加左右连续性。换成身体姿态控制主题后，核心任务变为陆地姿态对照、扶栏姿态体验、移动姿态观察，评价改为静态/移动姿态对照。未掌握“安全与装备”时不输出上述冰上练习。

以上仅为软件规则对比，不证明30人1教练方案安全；所有容量、分组、职责与活动时间均待专业现场复核，不能直接实施。

## 本地接口和安全

- `GET /api/v1/lesson-plans/themes`：24项来源与先修清单，仅可直接 loopback 访问。
- `POST /api/v1/lesson-plans/adaptive-draft`：本地会话、精确 Origin、`X-CoachLoop-Console: 1`、JSON；复用原请求体大小、重复键和脱敏错误保护。**不能用生产 Bearer 调用这个本地接口**。
- 原 `POST /api/v1/lesson-plans/draft` 保留 V1 契约与内部 Bearer 校验；前端 V1.1 使用上述独立扩展。
- 不挂主服务、不暴露数据库/旧流程/文档；直接127.0.0.1客户端、Host白名单、无转发头、无WebSocket、SameSite/HttpOnly、CSP、no-store。新路由还验证服务端对象标记，误挂未保护应用也默认拒绝，不接受自报身份头。
- 用户文本只通过 DOM `textContent` 展示，无 HTML 解释、无持久浏览器存储。导出重算并逐字段对比原始数据，保护构造后嵌套篡改、引用、时长、密度分母、审核状态和布尔伪装数值。
- 会话仅授权本机生成草稿，不证明教师身份，不提供多用户隔离；禁止公网绑定、反向代理、端口转发。其他本机进程/用户不属于此简易会话隔离能力。

契约文件：`adaptive-prelesson-v11.request.schema.json`、`adaptive-prelesson-v11.response.schema.json`、`adaptive-prelesson-v11.openapi.json`。OpenAPI为本地控制台扩展，不是Coze插件或公开API发布声明。输出 `status=draft_ready` 仅表示草稿生成成功，绝不表示可安全实施；永远 `draft`、`requires_teacher_review=true`、`knowledge_status=unverified`。
